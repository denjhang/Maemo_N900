# REFLECTIONS — 为什么 N900 生态是软渲染的，以及这场复活的思考过程

2026-10-13，gldemo_imgui 收工当晚。技术结论都在另外四份文档里，这份记的是**决策与思考过程**——为什么这么判断、为什么这么选。过程和结论同样重要，这是给"下一个会话"也是给"下一个人"的。

## 一、N900 生态为什么几乎全是软渲染？——平台三重锁

实验事实：同一块 SGX530，锁在 GTK/合成器路径里全系统卡顿，直通管线 81 FPS 满帧。硬件没问题，问题在架构选择。三重锁：

1. **Hildon 桌面 = GTK/Clutter**。Clutter 本是 GL 场景库，但诺基亚出厂把合成器锁在 CPU 路径——省电、SGX 闭源驱动当年不稳（我们亲历：纹理 2048 上限、数组未启用直接楔死管线、X server 无 XI2）。
2. **Xorg 1.6 + EGL surface 支持残废**。全屏这种基本需求都要靠 override_redirect 或 hildon-desktop 私有协议，裸 X11 应用没人伺候。
3. **应用生态全是 GTK widget**。为几百万台（且已停产）的封闭 GPU 机器写 GLES，投入产出比极低。

所以不是社区"瞎做"，是**诺基亚自己把 GPU 锁进保险柜**——而 glmemperf 的存在证明他们内部知道正确答案。社区里挖出来的人（glmemperf 作者、PPSSPP maemo 移植者）是极例外的偷渡者。

## 二、"粗制滥造的移植"的公道话——激励结构

大量移植质量差，本质是激励：闭源驱动 + 无文档 quirk + 用户量小 → 认真移植投入产出比太低 → "能跑就交差"。PPSSPP 能打，恰因为它反着来：把 maemo EGL 路径整个摸穿再动手——和我们这两天干的是同一件事，早了十几年。

安卓模拟器效率高的原因同理：GPU 驱动开源化、HAL 标准化、NDK 直接暴露 GLES——开发者不用考古。**差距不在人，在考古成本。**

## 三、"AI 一天击穿生态"的分解——速度是三个东西叠出来的

1. **前人的遗产都在**：glmemperf 的全屏答案、SDL 的 X11 驱动、PPSSPP 流程、播放器 V16 的字体配方。AI 干的是高速考古 + 拼图。当年单个大佬要几个月，主要成本是检索碎片，不是知识本身不存在。
2. **试错回路的压缩**：改一行 → 交叉编译 → SSH 部署 → 手机 62fps 看结果 = 30 秒。击穿生态的本质是迭代次数。2009 年的回路是 tarball + scp + 3.5 寸屏看 printf。
3. **人的部分不可替代**：硬件在手、方向判断（"看 glmemperf"、"看播放器 V16"、"用本地方法下载"）、品味判断（"糊了"、"点对点"）。洞见被档案化之后，执行层被 AI 平权——**当年稀缺的不是知识，是把散落知识拼成可用系统的耐心头脑**。

## 四、论坛时代的落幕——从绝望到笑谈

论坛（塞班/maemo.org garage）一度是这一切知识的唯一载体。人肉检索、口口相传、大佬隐退即失传。论坛没了，一度让人绝望——觉得那套"凿功"的传承断了。

后来发现它们没有失传：**帖子、源码、博客被蒸馏进了模型**。我们这两天的每次"参考 XX 源码"，本质上是在和当年论坛里的大佬们隔空合作。七夜、天地道们当年在无资料环境里靠反汇编硬凿的姿势，和今天"多看几个源码、对照实验、别死磕"的方法论一脉相承。工具换了，凿功传下来了。

论坛回不去了，但"发教程的论坛大佬"换了个形态回来了：git repo + 避坑文档 + 可复现配方。精华帖的终极形态是 `GLDEMO_IMGUI.md`。

## 五、这个 repo 的真实价值——让"击穿"可重复

- 2009 年的硬件 + 2026 年的工具链 = 81 FPS GUI + 七场景演示 + 可触摸停靠 ImGui，一天。
- 方法论沉淀在四份技术文档 + 本文件里，换个人照单执行也能复现。
- 嵌入式视角（用户原话）：性能只够跑原生 C 的设备，"AI + 原生 C/C++ + 极简运行时 + 直通管线"就是降维打击——对今天所有跑不动桌面 Linux 的低端嵌入式（路由器、车机、工控屏）依然成立。不用穿越改写历史，历史正在被补写。
