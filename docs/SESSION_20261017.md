## 第二阶段：窗口尺寸 + 触摸输入（同日追加）

### 问题
1. 窗口太大（440×320 默认），Flappy 是竖屏游戏，宽度应减半
2. 触摸点击完全不响应（v7 只处理了空格键）

### 方案

**窗口尺寸（通用机制）**：新增可选导出 `imapp_pref_size(float* w, float* h)`。
- 宿主 `dyn_scan` 时 dlsym 读取，存入 `DynApp.pref_w/pref_h`
- 首次打开时用 `ImGuiCond_Always` 应用一次（**能覆盖 imrun.ini 里存的旧尺寸**）
- 插件声明 400×420（竖屏比例，桌面可用高 480-48=432）
- 已写入 [IMAPP_SPEC.md](./IMAPP_SPEC.md)

**触摸输入**：恢复到早期版本验证过的写法——
```cpp
bool tapped = ImGui::IsWindowHovered(...) && ImGui::IsMouseClicked(0);
bool keyed  = IsKeyPressed(Space/UpArrow/Enter);
```
关键在于 `IsWindowHovered()` 限定**只有窗口内点击**才触发（点标题栏/桌面/任务栏不误触）。

### 自动化验证的突破

- **截图**：一直用 `/dev/fb0`（见 SESSION 第一阶段）
- **输入注入**：uinput 合成的设备 Xorg 不认（xorg.conf 静态绑定 TSC2005），
  改用 **XTEST**（libXtst.so.6 的 XTestFakeMotionEvent/ButtonEvent），成功注入点击
- **状态判定**：不能只看"画面有无差异"（桌面动画每帧都在变），要看游戏状态特征——
  MENU/GAMEOVER 中央有暗底衬提示、PLAYING 没有；管道用绿色像素计数

### 验证结果
- 窗口尺寸：400×420 窄窗口，不遮任务栏 ✅
- 触摸：XTEST 点击 → MENU→PLAYING→GAME OVER→点击重来，全流程响应 ✅
- 纹理：背景/城市天际线/绿管道/小鸟全部正确渲染 ✅

## 完成的工作

### 1. PNG 纹理加载系统（主程序 imgui_gles1.cpp）
- 集成 stb_image（仅 PNG、内存加载）
- 新增导出 API：
  - `imrun_load_png(const char *path)` → `ImTextureData*`
  - `imrun_register_texture(ImTextureData*)` → 注册到 `UserTextures`
  - `imrun_register_texture_and_get_id(ImTextureData*)` → 注册 + 立即上传 + 返回 GL TexID
- 关键机制：必须用 `ImGui::RegisterUserTexture()`（加到 `g.UserTextures`），因为 `PlatformIO.Textures` **每帧被 `UpdateTexturesEndFrame()` 清空重建**

### 2. 修复符号扩展 bug（画不出的根本原因）
GL 纹理 ID ≥ 2^31 时，`(intptr_t)` 转 64 位 ImTextureID 会**符号扩展**成无效值。
修复：一律 `(ImTextureID)id` 零扩展。涉及 upload/destroy/draw/register 全部位置。

### 3. 修复宿主窗口契约 bug（窗口空白主因）
插件 `imapp_frame` 误调 `ImGui::Begin/End` 开了流氓第二窗口。
修复：删掉 Begin/End，直接往宿主窗口 draw list 画；游戏用虚拟 800×480 坐标系 + 映射。

### 4. Framebuffer 截图自动验证（build/test_visual.py）
- N900 无截图工具，但 `/dev/fb0` 可读（800×480 RGB565, stride 4096）
- SSH 通道流式读 `dd if=/dev/fb0`（设备 /tmp 太小、无 base64，不能落盘/编码）
- 本地 numpy 解析 → PIL PNG → 像素分析（天空蓝/绿/黄占比）
- `python test_visual.py` 一键：部署 → 自动开应用 → 截图 → 分析 → 结论
